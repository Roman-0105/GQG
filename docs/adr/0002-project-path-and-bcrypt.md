# 0002 — Перенос проекта из-за "&" в пути и замена bcrypt

- Статус: принято
- Дата: 2026-09-05
- Автор: architect (по итогам запуска Этапа 00 на машине разработчика)

## Контекст

При первом запуске на локальной машине разработчика обнаружилось: путь
`C:\Users\Roman&Lera\Desktop\GQS` содержит символ `&`. Windows `cmd.exe`,
через который npm запускает почти любой lifecycle-скрипт и любой бинарник
из `node_modules\.bin` на Windows, интерпретирует `&` как разделитель
команд и рвёт абсолютный путь пополам — независимо от кавычек вокруг
команды. Это дважды привело к падению установки/сборки:

1. `bcrypt` не мог собрать нативный модуль (`node-pre-gyp install` падал
   с `Cannot find module 'C:\Users\@mapbox\node-pre-gyp\...'` — путь
   обрублен на `&`).
2. `prisma migrate dev` падал с той же природой ошибки при вызове
   `node_modules\.bin\prisma.cmd`.

Проблема системная: она будет повторяться в любом npm-скрипте, что
запускается через `cmd.exe` (сборка, тесты, будущие CLI-инструменты),
пока путь содержит `&`.

## Решение

1. **Перенести весь проект** с `C:\Users\Roman&Lera\Desktop\GQS` на
   `D:\Projects\GQS` (путь без спецсимволов), сохранив git-историю
   (обычное копирование `.git` вместе с рабочим деревом). Старая папка на
   Рабочем столе оставлена как есть — не используется для разработки.
2. **Заменить `bcrypt` на `bcryptjs`** в `apps/api` — тот же API
   (`hash`/`compare`, обе версии асинхронные), но чистый JS без нативной
   компиляции через `node-gyp`/`cmd.exe`. Это отдельно устраняет первую
   причину падения и снижает будущий риск: on Windows any native addon
   remains fragile to paths with special characters even after переезда,
   а bcryptjs — нет.

## Альтернативы

- Экранировать путь в каждом отдельном вызове (`cmd /c "..."` с ручным
  квотированием) — отклонено: пришлось бы чинить каждый инструмент
  отдельно (nest, vite, jest, playwright...), хрупко и не масштабируется.
- Переименовать сам профиль пользователя Windows (`C:\Users\Roman&Lera`)
  — отклонено: рискованная операция на уровне ОС, может сломать другие
  приложения, привязанные к старому пути профиля.

## Последствия

- Рабочая копия проекта отныне — `D:\Projects\GQS`. `README.md` и любые
  будущие инструкции ссылаются на этот путь.
- `.claude/agents/*` скопированы вместе с проектом — команда агентов
  доступна на новом месте без дополнительной настройки.
- Правило на будущее (для `devops`/`architect`): при разворачивании на
  новой машине или новой рабочей станции проверять путь на спецсимволы
  (`&`, `%`, `!`, пробелы в редких edge-case) до `npm install`.
