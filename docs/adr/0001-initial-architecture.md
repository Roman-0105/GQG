# 0001 — Начальная архитектура

- Статус: принято
- Дата: 2026-09-05
- Автор: architect

## Контекст

Нужно выбрать стартовый стек и структуру репозитория для платформы КЕРН,
не блокируя команду агентов на дальнейших этапах. Требования из
`docs/project-plan.md`: гибкая ролевая модель, настраиваемый расчёт ЗП,
офлайн-первая форма табеля для поля, аналитика на нескольких срезах
времени, локальное развёртывание.

## Решение

- **Монорепозиторий** с npm workspaces: `apps/api` (backend),
  `apps/web` (веб-панель и полевое PWA). Единый репозиторий проще
  поддерживать локально одной командой агентов, чем несколько.
- **Backend:** NestJS (TypeScript) + PostgreSQL + Prisma. Сквозная
  типизация от схемы БД до контроллеров снижает риск рассинхронизации
  ролевой модели и формул расчёта между слоями.
- **RBAC как первоклассная сущность:** право = `(ресурс, действие,
  область видимости)`, хранится в таблицах `Role`/`Permission`, а не
  зашито в код по названию роли. Это прямое требование из раздела 2
  плана — владелец должен собирать роли без правки кода.
- **Frontend:** React + Vite + Tailwind. Полевое приложение — то же
  React-приложение как PWA с офлайн-очередью, а не отдельный
  мобильный код — снижает объём поддержки на локальной разработке.
- **Единая схема Prisma** сразу отражает всю доменную модель (раздел 3
  плана) — Компания → Участок → Бригада → Сотрудник, плюс сквозные
  Табель и РасчётЗП/PayrollLine — чтобы backend-dev не переизобретал
  структуру данных при реализации каждого модуля отдельно.

## Альтернативы

- **Python/Django** вместо Node/NestJS — не выбран по умолчанию, так
  как это открытый вопрос пользователя (план, раздел 10, пункт 2);
  ролевая модель и доменная модель в этом ADR от стека не зависят,
  переход возможен без пересмотра плана.
- **Отдельное нативное мобильное приложение** для бригадира — отложено
  в бэклог v2 (план, раздел 9, этап 07); офлайн-PWA закрывает сценарий
  с меньшими трудозатратами на старте.

## Последствия

- Все последующие модули backend обязаны использовать RBAC-guard
  (`src/common/rbac`), а не собственные проверки `if (role === ...)`.
- Изменение схемы Prisma, ломающее обратную совместимость, требует
  нового ADR.
- До подтверждения пользователем стека (открытый вопрос) любая
  реализация в NestJS считается предварительной, но переносимой:
  доменная модель и контракт API документируются отдельно от кода.
